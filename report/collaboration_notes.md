# 大模型协作与纠错记录

collaboration_record.json 是本项目对应会话中可见用户消息与助手回复的原文节选，来自本机实际会话记录；未包含系统指令、开发者指令、隐藏推理和工具原始输出。节选不等于全部历史对话，不将本摘要表述为完整逐字导出。时间、原文角色和范围保留在 JSON 中。

## 关键判断与观察

1. 用户要求统一 TinyMaix 模型与推理路径，并按真实 CPU/NPU 时间填写。旧 edge_infer 与 TinyMaix 的模型、算子和计时条件不同，因此本版冻结 MNIST/KWS 模型身份，保留原 CPU 算法与同一输入，不直接搬用旧 11×/77×结果。
2. 首次调用、NPU 指令流缓存未命中与热缓存的时间不同。当前版显示全部三档，主结果明确为热缓存。MNIST 后续复用权重，KWS 没有持久权重复用，避免把“未命中”误称为全部冷启动。
3. 浏览器会按 AudioContext 采样率重采样 WAV，导致同一个 0a.wav 的特征变化。修改为优先解析原始 PCM WAV，再走冻结的 FBank 预处理。修复后特征 SHA256 与基准完全相同，主机测试与实际文件选择器均已验证。
4. 早期曾按用户当时要求恢复其他平台的资源与功耗资料。2026-11-02用户明确要求全部统一为XC7A100T，当前交付按最新指示重建、复测和替换，早期保留口径已由本次数据取代。
5. 在中文临时输出路径执行重建时，GCC size 输出包含本地编码，UTF-8 控制台解码失败。编译和链接本身已完成；修改非关键日志的解码容错，并在英文路径重新构建两模型，保存实际结果。该修改只影响日志显示，不改算子或计时固件。
6. 用户要求恢复原 GUI 的独立弹窗形式。新增 Tkinter 前端，沿用原 Windows Ink 手绘板适配器，共用现有推理与预处理后端。窗口中的两模型实测与冻结基准相同，原生音频导入、播放及 ToDesk 虚拟麦克风录音链路通过验证。

## 证据与提炼

- 真实板测及每轮 CPU/NPU 全层与最终输出比对：data/benchmark.json、tools/tinymaix_live_gui/runs/。
- 主机 WAV、静音、异常 PCM 与启动器验证：tools/tinymaix_live_gui/host_checks.json。
- 构建与资源验证：build/reports/；冻结模型/位流身份由根 manifest 与包自检保护。
- 可复用经验沉淀为 skill/ 中的身份绑定、有限超时、完整输出比较和正反例工具。其适用范围、失败条件和验证边界在 skill/README.md 中列出。

以上为实际观察的整理，不构造不存在的用户提问、模型回答或成功实验。原始完整工程和此前过程材料另有全量快照。


## 2026-11-02 XC7A100T统一修订

根据用户要求，将正式材料、双语海报和活动构建入口统一为XC7A100T、VexRiscv/TinyMaix、50 MHz。Vivado 2026.1首次构建因FIFO BRAM映射超量而失败，随后显式设置部分FIFO为分布式RAM，在保持容量的条件下重新实现并上板复测。当前资源、时序、功耗和原始报告见build/reports/implementation_20261102.json，完整推理复测见board_retest_20261102.json。旧交互记录仅反映当时决策，当前有效参数以本次报告为准。
